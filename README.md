# VCF Analyzer

15×15 連珠／五子棋 VCF 局面分析、題庫與題目產生工具。

正式網站：<https://5871224.github.io/VCF/rapfi/>

## 目前功能

- 黑方／白方單組 VCF。
- 多組 VCF，支援高速與嚴格剪枝。
- 多組搜尋可選「活四不搜後續」，已有直接五或活四時不再展開其他死四勝法。
- 最短 VCF，完整證明與限制中止狀態分開顯示。
- 單一路線 VCF 防守與全部 VCF 防守。
- VCT 候選點分析。
- 補黑／補白找 VCF，支援「最速」與「最短」。
- 有禁、無禁、自由三種規則。
- 黑棋禁手標示：長連 `6`、四四 `44`、三三 `33`。
- 圖片、截圖與手機相機棋盤匯入，採輪廓、Hough、15 路局部校正與可手動修正的半透明單畫布預覽。
- Supabase 共用題庫。
- 1～10 步 VCF 題目產生器。
- 題目答案與黑方／白方／雙方 N 點顯示。
- 工作台與題目產生器的人工設定欄位會記住使用者上次設定。

## 正式執行架構

`/rapfi/` 使用 Bitboard C++ WebAssembly：

```text
makevcf.html
  → rapfi/vcf-bitboard-main.js
  → rapfi/vcf-bitboard-worker.js
  → rapfi/engine/vcf-bitboard-engine.js / .wasm
```

題目產生器使用獨立 Worker，不共用或中止主分析 Worker：

```text
makevcf-generator-core.js
  → rapfi/vcf-bitboard-worker.js
  → rapfi/engine/vcf-bitboard-engine.js / .wasm
```

GitHub Pages 建置由 `.github/workflows/pages.yml` 執行，正式輸出包含：

- `/index.html`
- `/makevcf.html`
- `/rapfi/index.html`
- `/rapfi/lab.html`
- Bitboard 及棋型 WebAssembly 檔案

## 規則

| 值 | 名稱 | 說明 |
|---:|---|---|
| `0` | 自由 | 黑白長連皆算勝；黑白棋型皆取 9 格 |
| `1` | 無禁 | 黑白皆無禁手，長連不算勝也不算負；黑白棋型皆取 11 格 |
| `2` | 有禁 | 連珠規則；黑棋有禁手，黑棋取 11 格、白棋取 9 格 |

自由規則值為 `0`，不得使用會把 `0` 當成預設值的真假值回退寫法。所有 Worker 搜尋、精簡與防守請求都必須明確傳入規則。

## 使用者設定記憶

以下人工設定會使用瀏覽器 `localStorage` 保存，重新整理或下次開啟時自動恢復：

- 規則與分析色。
- 多組剪枝、時間限制、節點限制、補子搜尋模式與搜尋勾選項。
- 題目產生器攻方、生成步數、加成數值，以及排序、補子、唯一題等動態設定。

設定記憶層會自動監聽工作台與題目產生器容器內後續新增的數字欄位、下拉選單、勾選框與單選項。檔案選擇、棋盤內容、搜尋結果及答案顯示等一次性狀態不保存。

## VCF 搜尋模式

| 模式 | 用途 |
|---|---|
| `single` | 最快找到第一組 VCF |
| `multi` | 在指定深度內列舉最多 64 組 VCF |
| `shortest` | 逐層找到最短深度的一批 VCF |
| `shortest-one` | 找一組路線並完整排除更短路線；限制中止時保留目前最佳結果 |

多組剪枝：

- `fast`：完整同盤無解剪枝，加上已完整證明的勝型集合子集剪枝。
- `strict`：只使用完整黑白棋盤完全相同的同型判定。
- 「活四不搜後續」：快速、嚴格共用；同一盤面若有直接五或活四，只保留全部終局候選，不再搜尋後續單防死四分支。預設不勾選。

多組路線先以原始攻守手順做子集去重，再精簡保留路線。

## 搜尋限制

工作台提供：

- 時間限制：秒。
- 節點限制：百萬節點。
- `0` 代表不限制。

多組 VCF、最短 VCF、補子搜尋及題目產生器共用這兩個輸入。多組型搜尋會把時間、節點限制及「活四不搜後續」封裝在 32-bit `maxNode`；不得以固定 500 萬節點取代使用者輸入。

達時間或節點限制時可保留已找到結果，但不得誤報為完整列舉、已證明最短或已證明唯一。

搜尋效能文字格式固定為：

```text
7.4351 秒，30,123,123 節點，4,123,123 節點/秒
```

## 補子搜尋

補子搜尋只保留：

- 「最速」：每個補子點使用 `single`。
- 「最短」：每個補子點使用 `shortest-one`。

每個落點分別顯示：

- `5`：直接連五。
- `4`：形成四。
- 數字：該補子點可形成的 VCF 步數。

搜尋完成後，在所有 VCF 數字中以圓圈標示**數字最大的落點**；`4`、`5` 不參與圈選。「最短」只代表每個落子點使用該點的最短 VCF，不代表圈選全盤最小數字。

## 題目產生器

題目產生器可指定：

- 攻方。
- 有禁／無禁／自由規則。
- 1～10 步。
- 沿用棋子加成。
- 棋子集中加成。
- 是否依加成高低排序。
- 是否補齊黑白子數。
- 三型加成。
- 是否只保留目標 VCF。

搜尋規則：

- 一般候選使用 `shortest`。
- 「只保留目標 VCF」使用 `multi`，最多 64 組。
- 最大深度為 `2 × 目標步數 + 1` ply。
- 共用工作台的時間、節點、剪枝及「活四不搜後續」設定。
- 題目產生開始時取得設定快照，產生期間停用相關控制項。
- 唯一題只要搜尋中止、回傳 64 組、達時間限制或達節點限制，就不得宣告唯一。

加成規則：

- 「沿用棋子加成」計算沿用攻方棋，以及模板 X 點或五點原有的守方棋；A 不計入。
- 「棋子集中加成」以目前盤面全部黑白棋的座標平均值為分布中心，新死四模板中央點越接近中心，加成越高。
- 未勾選排序時依權重隨機；勾選「依加成高低排序」時依總權重由高到低驗證，同權重隨機排列。

## 題庫

- 題庫唯一資料來源為 Supabase。
- 每題保存 225 格 `board` 與 `attacker`。
- 載入題目後使用工作台目前規則。
- 不保留瀏覽器 `localStorage` 題庫、資料搬移流程或其他儲存相容層。

## 開發與驗收

修改搜尋核心至少要執行：

- Native C++ 編譯及自我測試。
- LTO SIMD Wasm 編譯。
- Wasm ABI 測試。
- JavaScript 語法檢查。
- 相同盤面、規則及限制下的結果與節點比較。

修改題目產生器至少要確認：

- 專用 Worker 不影響主分析 Worker。
- 規則 `0`、`1`、`2` 正確傳入所有請求。
- `shortest`、`multi`、`fast`、`strict` 使用正確。
- 時間、節點、深度與 64 組上限正確傳入。
- 時間或節點為 `0` 時保持不限制。
- 搜尋達限制時不誤判最短或唯一。
- 手機版與桌機版皆可操作。

正式功能的小型修改直接提交到 `main`；提交後確認 GitHub Pages 建置與部署狀態。
